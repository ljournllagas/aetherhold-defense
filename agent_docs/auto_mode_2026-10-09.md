# Auto mode — 2026-10-09

Implementation, verification and production publication are complete. The fresh independent review cleared the whole change with zero Critical/Important/Minor findings and independently ran 129 passing tests.

## Behavior

One HUD switch and the same setting in Pause control automatic waves and situational relic use. A toggles it, ignoring repeats, replayed keyboard events and editable targets. Every new/restarted run starts OFF; Continue Endless retains the setting.

Auto waits five eligible real seconds between waves, independent of combat speed. Manual Start skips the wait. Pause, background pause, manual dialogs and manual Meteor targeting suspend Auto. Victory still requires the player's Finish/Continue choice. Tower purchases, evolution, targeting, speed and score submission remain manual.

Relics use their existing effects. Full-health repairs and active duplicate buffs wait; later useful items can bypass them. Meteor uses the deterministic largest eligible enemy-centered cluster (three victims or a boss). All overflow rewards are retained without a fourth slot, replacement or discard. Auto ON permits victory choices with unopened retained rewards; OFF preserves manual FIFO choices.

## Execution rulings

1. Managed worktree on `codex/auto-mode`, then authorized fast-forward integration into `main`: preserves the original checkout; costs an integration step.
2. Use installed Phaser `eventemitter3` and ES2020-safe indexed test call access: avoids a new dependency or compiler change; test emitter differences are checked with native input.
3. Auto uses actual visible-frame timestamps, retaining the last valid monotonic timestamp, rather than Phaser's smoothed combat delta: prevents early starts without changing combat; timing regressions and native waits verify the risk.
4. Stop the extra MainMenu scene only in QA browser setup: global QA launch otherwise leaves menu artwork/buttons behind letterboxed fields; normal production entry is checked separately.
5. Settle native browser actions across two animation frames: assertions observe processed Phaser input; costs slower verification, with no production input change.
6. Ignore already-handled keydown timestamps: tracing proved Phaser can replay the original non-repeat event before clearing its queue; ordinary presses and repeats are verified, but distinct presses sharing the same timestamp are ignored.
7. Keep existing combat-timing, preview and staged-loading follow-ups separate: Auto does not affect them; their existing limits remain unfixed.
8. Keep tower automation, strategy assessment and balance tuning excluded: the player decides when to enable Auto; it cannot guarantee a successful defense.
9. Keep physical touch, other browsers and extreme endless-wave performance unverified: current evidence is bounded Chromium/visibility integration; platform or extreme-load issues may remain.

Physical touch, other browsers, human balance playtests and optional balance simulations were not run. Coarse-frame attack scheduling, richer upgrade previews and staged asset loading remain separate work.
