# I16 — Expansion boss authored-action consumption

**Task ID:** I16
**Problem ID:** final-boss-authored-action-consumption

## Finding

All seven expansion boss atlases register authored `special` and `phase_two` clips. Current natural runtime selection is incomplete: Mireheart Hydra is the only expansion boss with `setCampaignState` hooks for these clips, and its first natural phase-two edge is masked by the simultaneous cast warning. Drowned Oracle, Iron Tyrant, Stormmaw Prime, Umbral Regent, Rift Sovereign, and Aether Devourer update procedural overlays but never request either clip from a natural `CampaignBossSystem` transition.

The per-world browser gates establish that the clips can play when QA calls `EnemyView.playAction` directly. They do not establish natural transition consumption. The World 9 gate makes this distinction explicitly: it records the natural portal state first, then loops over direct `playAction('attack'|'special'|'phase_two')` checks (`w9-full-atlas-runtime.cjs:728`, `w9-full-atlas-runtime.cjs:731`).

## Evidence and per-boss transition map

`artManifest.ts:42` defines the shared expansion boss rows (`special` row 3 and `phase_two` row 4, eight frames each); every expansion boss entry reuses that state set (`artManifest.ts:161`). `campaignAnimationDefinitions` emits one-shot definitions for both states (`artManifest.ts:67`, `artManifest.ts:75`). `EnemyView.playAction` only starts registered one-shots, returns their duration, and enforces action priorities and death lock (`enemyArt.ts:73`, `enemyArt.ts:371`). The authored clips are therefore available to the presentation API; availability alone does not connect them to boss mechanics.

For World 5–10, the `setCampaignState` branches contain only overlay updates; there is no `preferAction`, `nextPhasePose`, or `playAction` call in those six branches (`enemyArt.ts:431`, `enemyArt.ts:456`). `CampaignBossEvent.presentationAction` only permits `'buff'`, and `GameScene.tickCampaignBosses` only dispatches that action; normal game code separately dispatches `death` (`bosses.ts:93`, `GameScene.ts:3090`, `GameScene.ts:2004`). Normal simulation calls the boss system before enemy movement, while rendered presentation state is passed to the visual later (`GameScene.ts:3225`, `GameScene.ts:3308`).

## Verification gap and minimal integration option

`campaign-v5-boss-mechanics.test.ts` checks the real boss warning/effect timelines and mutations for Worlds 5–10, while `campaign-enemy-animation.test.ts` checks generic action priority/death/locomotion and Hydra’s manually supplied states. The six-boss cue test uses provisional art and explicitly expects no sprite action (`campaign-enemy-animation.test.ts:264`). No checked-in test connects a real boss-system transition to a `special` or `phase_two` request. The Hydra phase-two animation assertion is also a synthetic edge with telegraph false, so it misses the natural phase-2-plus-warning collision.

The smallest explicit presentation contract is to extend the existing `CampaignBossEvent.presentationAction` from `'buff'` to include `'special'` and `'phase_two'`, then dispatch those through the existing `EnemyView.playAction` call site. Mark warning events as `special` and effect-resolution/phase-entry events as `phase_two` according to the table; leave Stormmaw without a phase-two event unless its design explicitly defines one. This keeps actions presentation-only and leaves `phase`, `phaseLabel`, callout text, warning durations, summons, resistance/armor/speed effects, route advance, and save state under the current boss simulation. The shared clips are one-second one-shots (8 frames at 8 fps), shorter than each current named warning (1200–1500 ms); playing through the existing API preserves the current `death` lock/priority and resumes the latest idle/walk pose after completion.

An integration test should drive each actual transition and observe both the named warning/effect state and the requested clip. In particular, cover Hydra’s `{phase 1, telegraph off} → {phase 2, telegraph on} → summon resolution` sequence and assert that both actions are consumed in order; cover World 5’s pending-vs-active resistance edge; and assert that Stormmaw does not invent a boss phase. Existing per-world QA scripts for Worlds 5–8 and 10, and the World 9 full-atlas gate, manually call `playAction` for candidate clips; that is valid art-playability evidence only (`w5-stage-gate.cjs:368`, `v12-world6-gate.cjs:322`, `v13-world7-public-gate.cjs:386`, `v14-public-runtime.cjs:389`, `w10-stage-gate.cjs:391`, and `w9-full-atlas-runtime.cjs:730`).
